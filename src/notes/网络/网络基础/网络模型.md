### TCP/IP 上下层协议 理解

当服务器 A 使用 HTTP 协议访问服务器 B 时，A 会先处理第七层协议的数据，然后往下，你可以理解为包装，第一层包第二层，以此类推，第七层在最里面；当数据包到达服务器B 时，B 先拆解最外面的协议包（也就是第一层），然后一层层处理，最后才到第七层的应用层数据；

### 3. “虚假”的真实：我们是如何找回源 IP 的？

为了解决 Nginx 把 IP 改掉的问题，工程师们在“货物”里塞了**小纸条**。

1. **七层方案（HTTP Header）：** Nginx 在拆开包装发现原件 IP 是 `1.2.3.4` 时，它在重新包装 HTTP 货物时，往 Header 里塞了一行：`X-Forwarded-For: 1.2.3.4`。 你的 Golang 应用读取这个 Header，就能知道“幕后黑手”是谁。
2. **四层方案（PROXY Protocol）：** 如果不是 HTTP 协议（比如数据库连接），没有 Header 怎么办？人们发明了 **Proxy Protocol**。它在建立连接的最开始，先发一串简单的文本说明：“嘿，真正的发件人是 1.2.3.4”。

### 4. 特殊情况：内网 NAT (网络地址转换)

如果你在公司内网，你的“真实 IP”其实在经过公司大门（企业路由器）时就已经被改掉了。

- 你的电脑：`192.168.1.5`（这是私网地址，公网不认）。
- 公司路由器：把它改成公司宽带的公网 IP `202.96.x.x` 发出去。
- **结果：** 目标服务器看到的“源 IP”是公司路由器的 IP，而不是你电脑的。在公网环境下，**这被认为是“真实”的源 IP**，因为只有这个 IP 才能收得到回信。
