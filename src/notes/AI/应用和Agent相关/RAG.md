# RAG

**RAG（Retrieval-Augmented Generation，检索增强生成）** 是目前大模型落地最核心的技术之一。简单来说，它就像是给大模型配了一个“开卷考试的翻书助手”。当用户提问时，助手先去私有知识库里把相关的资料找出来（检索），然后再把资料递给大模型，让大模型看着资料来回答问题（生成）。

一个典型的 RAG 工作流主要分为两个阶段：**数据准备阶段（离线）** 和 **检索与生成阶段（在线）**。

## 一、 RAG 核心工作流

### 1. 数据准备阶段（把书放进书架）

这个阶段发生在用户提问之前，目的是把海量的文档变成文档数据库。

- **文档解析（Parsing）：** 把 PDF、Word、Markdown 等各种格式的文档读进来，转成纯文本。
- **文本切块（Chunking）：：** 大模型一次能读的字数有限，所以需要把长文章切成一小段一小段的（比如每段 300~500 字）。
- **向量化（Embedding）：** 利用 **Embedding 模型**，把切好块的文本转换成一串数字（向量）。这串数字代表了这段文本的“语义”。
- **入库（Storage）：** 把这些向量和原始文本一起存进**向量数据库**（Vector DB，如 Milvus、Pinecone、Chroma 等）里。

### 2. 检索与生成阶段（开卷考试）

当用户真正开始提问时，流程如下：

- **问题向量化：** 用户输入问题（例如：“公司年假怎么休？”），系统同样用 Embedding 模型把这个问题转成向量。

- **向量检索（Retrieval）：** 拿着问题的向量，去向量数据库里比对，找出最相似的 N 个文本块（比如找出那几段提到年假规定的管理办法）。

- **重排（Reranking，可选但重要）：** 刚刚粗筛出来的文本块，通过 **Reranker 模型** 进行精细化打分，把真正最相关的调整到最前面。

- **提示词拼接（Prompt Construction）：** 把用户的问题和检索出来的相关文本拼成一个大提示词。

  **示例提示词：** > “请结合以下已知信息回答问题。已知信息：[检索到的年假规定文本]。问题：公司年假怎么休？”

- **大模型生成（Generation）：** **LLM（大语言模型）** 阅读这些已知信息，组织语言，生成最终的准确回答。

## 二、 RAG 涉及到的三大核心模型

在整个流程中，主要有三类模型在各司其职：

| **模型类型**                            | **扮演的角色**           | **常见代表作**                                        | **核心作用**                                                 |
| --------------------------------------- | ------------------------ | ----------------------------------------------------- | ------------------------------------------------------------ |
| **1. Embedding 模型** (嵌入/向量化模型) | **“翻译官兼图书管理员”** | OpenAI `text-embedding-3`, BAAI `bge-large-zh`, `m3e` | 将人类的文字（问题和文档）转化成计算机能看懂的向量空间。文字相似度越高，它们的向量距离就越近。 |
| **2. Reranker 模型** (重排模型)         | **“精明的主审官”**       | BAAI `bge-reranker`, Cohere Rerank                    | 向量检索虽然快，但有时候不太精准（只看语义大方向）。Reranker 负责对初步检索出的文章进行“精细对比”，计算问题和文档的真实相关度，确保最核心的内容排在第一位。 |
| **3. LLM 大语言模型** (生成模型)        | **“负责作答的学霸”**     | GPT-4o, Claude 3.5, DeepSeek-V3, Llama 3              | 负责“理解”检索出来的资料，去掉噪音，发挥它强大的语言组织能力，给用户输出一个逻辑通顺、没有幻觉的最终答案。 |
