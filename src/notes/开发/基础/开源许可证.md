# 开源许可证

开源许可证决定了**别人可以对你的代码做什么、不能做什么**。常见的开源协议主要分为两大门派：**宽松型 (Permissive)** 和 **传染型/保护型 (Copyleft)**。

### 1. 一张图理清选择逻辑

- **你是否允许别人闭源修改并商用？**
  - **允许** $\rightarrow$ 选择 **宽松型许可证**（MIT, Apache 2.0, BSD）
  - **不允许**（强制要求修改后的代码也必须开源） $\rightarrow$ 选择 **传染型许可证**（GPL, AGPL, LGPL）

### 2. 核心开源许可证对比表

| **许可证**                    | **类型**        | **修改后必须开源？**   | **允许闭源商用？** | **专利授权保护？** | **代表项目**                    |
| ----------------------------- | --------------- | ---------------------- | ------------------ | ------------------ | ------------------------------- |
| **MIT**                       | 极度宽松        | ❌ 否                   | 是                 | ❌ 无               | Vue.js, React, Node.js          |
| **Apache 2.0**                | 宽松 + 专利保护 | ❌ 否                   | 是                 | 有                 | Android, Kubernetes, TensorFlow |
| **BSD (2-Clause / 3-Clause)** | 宽松            | ❌ 否                   | 是                 | ❌ 无               | Go 语言, Nginx                  |
| **GPL (v2 / v3)**             | 强传染型        | **是**                 | ❌ 否（不可闭源）   | 有 (v3)            | Linux Kernel (v2), Git (v2)     |
| **AGPL**                      | 网络级极强传染  | **是**（连云服务都算） | ❌ 否（不可闭源）   | 有                 | Grafana, MongoDB (早期)         |
| **LGPL**                      | 弱传染型        | 仅修改库本身时         | 是（动态链接时）   | ❌ 无               | FFmpeg (部分模块), 7-Zip (部分) |

### 3. 各许可证的核心特点拆解

#### 宽松型许可证（商业友好）

1. **MIT 许可证**
   - **特点**：最简单、最宽松。
   - **限制**：只要在副本中保留原作者的版权声明和免责声明，使用者可以做**任何事情**（商用、修改、闭源、再授权）。
2. **Apache 2.0 许可证**
   - **特点**：在 MIT 的基础上，增加了**明确的专利授权条款**。
   - **价值**：规定如果别人用了你的代码，不能反手就专利侵权问题起诉你；修改过文件的地方需要说明。适合大型商业企业开源项目。
3. **BSD 许可证**
   - **特点**：类似于 MIT，但 3-Clause 版本额外增加了一条：**不能用原作者或机构的名字来做市场推广/背书**。

#### 传染型许可证（保护开源生态）

1. **GPL (General Public License)**
   - **特点**：“霸王条款”与“开源卫士”。任何包含了 GPL 代码的项目，其整体衍生作品**必须也以 GPL 协议开源**（即“传染性”）。
   - **影响**：商业公司极度忌惮在闭源产品中包含 GPL 代码。
2. **AGPL (Affero GPL)**
   - **特点**：堵住了 GPL 的“云服务漏洞”。
   - **背景**：GPL 规定“软件分发”时才需开源，但很多 SaaS 公司（如 AWS）直接在云端运行 GPL 软件提供服务而不分发二进制文件，从而避开了开源义务。AGPL 规定：**只要通过网络调用该服务，就必须向用户开源**。
3. **LGPL (Lesser GPL)**
   - **特点**：对商业友好的弱传染协议。
   - **规则**：如果你只是**动态链接 (Dynamic Link)** LGPL 的类库，你的主程序不需要开源；但如果你**修改了 LGPL 类库本身**的代码，修改后的类库必须开源。非常适合基础函数库。
