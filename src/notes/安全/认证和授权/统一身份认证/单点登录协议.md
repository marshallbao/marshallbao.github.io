# 单点登录协议

## SAML

SAML（Security Assertion Markup Language）

### 原理

三个角色

| 角色                         | 中文理解     | 示例    |
| ---------------------------- | ------------ | ------- |
| **User（用户）**             | 使用系统的人 | 用户    |
| **IdP（Identity Provider）** | 身份提供方   | 飞连    |
| **SP（Service Provider）**   | 服务提供方   | jenkins |

### SAML 单点登录全过程

```
用户 → 系统A(SP) → IdP → 系统A

# 解释
1. 用户登录业务服务
2. 业务服务重定向到 IDP 
3. IDP认证完后，再重定向到 SP
4. 完成登录

# 
```

### SAML 配置过程

以 jenkins + 飞连为例子

```
1. 在飞连创建 saml 单点登录应用
2. 在 jenkins 配置 saml 单点登录,包括
	需要配置 IDP(飞连) 的 metadata（可通过 URL 或者具体文件），用于认证
	在 jenkins 拿到 Service Provider Metadata，也就是 jenkins 自己的 metadata,需要上传到飞连用于 IDP 来认证 SP
	
# 体现在具体文件就是
IDP（飞连）的 metadata
/var/jenkins_home/saml-idp-metadata.xml

SP(jenkins) 的 metadata
/var/jenkins_home/saml-sp-metadata.xml
```
